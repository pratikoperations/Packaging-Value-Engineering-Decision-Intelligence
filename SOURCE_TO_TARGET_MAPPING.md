# Source-to-Target Mapping

## Purpose
Map authoritative PVE outputs into PostgreSQL reporting entities and Power BI fields without changing SQLite persistence or analytical logic.

| PVE Source | Source Concept | PostgreSQL Target | Power BI Target | Rule | Validation |
|---|---|---|---|---|---|
| Project record | project ID, name, status, archived flag | `dim_project` | Project | Preserve authoritative ID | No duplicate or orphan project |
| Alternative record | alternative ID, name, baseline flag | `dim_alternative` | Alternative | Preserve ID and baseline flag | One declared baseline per dataset |
| Dataset version | dataset ID and version | `dim_dataset_version` | Dataset Version | Preserve immutable version | Match source version count |
| Threshold profile | threshold ID and version | `dim_threshold_profile` | Threshold Profile | Preserve exact version | Match source count |
| Scenario | scenario ID, assumptions, timestamp | `dim_scenario`, `fact_scenario_result` | Scenario | Preserve IDs and references | No cross-project link |
| Cost output | annual costs and savings | `fact_cost_analysis` | Cost and Savings | Load stored outcomes only | Exact numerical match |
| Qualification output | criterion, status, evidence | `fact_technical_qualification` | Technical Qualification | Copy stored status | Exact status match |
| Risk output | category, severity, status, mitigation | `fact_risk_assessment` | Risk Dashboard | Copy stored outcome; no reporting-side scoring | Exact status and count match |
| Threshold output | result, reason, version | `fact_business_threshold_result` | Threshold Outcome | Preserve stored result | Exact result match |
| Decision snapshot | snapshot ID, status, source references, timestamp | `fact_decision_snapshot` | Decision History | Append-only; preserve all references | IDs and timestamps match |
| Reporting load | load ID, timestamps, row counts | `pve_audit.reporting_load_run` | Refresh Metadata | Generated by load process | Successful complete load only |
| Reconciliation | expected, actual, variance, status | `pve_audit.reporting_reconciliation_result` | QA Metadata | Generated after load | Zero deterministic variance |

## Mapping Rules
- SQLite and Python remain authoritative.
- PostgreSQL contains a reporting projection only.
- Business statuses are copied, not inferred.
- Timestamps use UTC.
- Facts retain authoritative source IDs as alternate keys.
- Failed or partially reconciled loads are not exposed through approved views.
- Power BI imports approved views only.

## Change Control
Every new field or KPI requires an authoritative source, PostgreSQL target, Power BI target, transformation rule, reconciliation test, and approval before implementation.
