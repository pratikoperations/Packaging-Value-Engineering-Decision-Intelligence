# Gate 4 — Governed Standardised Portfolio Export MVP

## Status

Implementation candidate. This document does not authorize merge, release, deployment, reviewer requests, or Power BI service publication.

## Purpose

The export pack converts an already validated internal decision package into stable tabular files for Power BI Desktop and interview demonstration. It is a serialization layer only. It does not reproduce cost, material, technical qualification, risk, recommendation, or calculation formulas.

## Authoritative inputs

- governed synthetic dataset;
- `ScenarioResult` generated by `scenario_engine`;
- technical qualification outcomes;
- risk outcomes;
- recommendation result;
- validated decision package assembled by `src.exports`;
- explicit source commit and generated timestamp.

## Output files

1. `project_summary.csv`
2. `scenario_summary.csv`
3. `alternative_summary.csv`
4. `scenario_results.csv`
5. `technical_qualification.csv`
6. `risk_indicators.csv`
7. `recommendations.csv`
8. `assumptions.csv`
9. `data_dictionary.csv`
10. `export_manifest.json`

## Grain and relationships

- Project: one row per governed project.
- Scenario: one row per project and canonical scenario input fingerprint.
- Alternative: one row per project and packaging alternative.
- Scenario result: one row per scenario and alternative.
- Qualification: one row per scenario and alternative outcome.
- Risk: one row per scenario, alternative and risk indicator.
- Recommendation: one row per scenario and proposed alternative.
- Assumption: one row per scenario, alternative and assumption.
- Data dictionary: one row per exported column.

Power BI relationships should use single-direction dimension-to-fact filtering. Do not create fact-to-fact or many-to-many relationships.

## Power BI model

Dimensions:

- `DimProject` from `project_summary.csv`
- `DimScenario` from `scenario_summary.csv`
- `DimAlternative` from `alternative_summary.csv`

Facts:

- `FactScenarioResult`
- `FactQualification`
- `FactRisk`
- `FactRecommendation`
- `FactAssumption`

Power BI may aggregate exported values but must not recreate recommendation, risk, qualification, technical approval, cost, or material logic.

## Units and currency

- monetary values preserve the project ISO currency code;
- unit cost uses `<currency>_per_case`;
- dimensions use millimetres;
- case weight uses grams;
- annual material uses kilograms;
- annual volume preserves the governed source unit;
- percentages are exported as percentage-point numeric values.

No currency or engineering-unit conversion occurs in the exporter.

## Governance controls

The exporter rejects any decision package whose `dataset_type` is not `synthetic_demo`.

The manifest records:

- export schema version;
- source repository;
- source commit;
- generated timestamp;
- dataset schema version;
- confidentiality class;
- file row counts;
- file column counts;
- SHA-256 hashes;
- read-only, synthetic-only and no-formula-recalculation controls.

## Determinism

With identical dataset, decision package, scenario name, adjustments, source commit and generated timestamp, the exporter must produce byte-identical files. Row order, column order, identifiers, null representation, line endings and JSON key order are stable.

## Generate the governed synthetic example pack

Run from the repository root after installing declared dependencies:

```bash
PYTHONPATH=. python tools/generate_portfolio_export.py \
  --scenario-id <governed-scenario-id> \
  --source-commit <exact-feature-sha> \
  --generated-at 2026-08-01T12:00:00Z \
  --output examples/portfolio_export
```

The generated directory is the governed synthetic example pack. The exact scenario ID must come from `data/demo/governed_synthetic`.

## Validation

Focused tests:

```bash
PYTHONPATH=. python -m unittest tests.portfolio_export.test_exporter
```

Complete repository suite:

```bash
PYTHONPATH=. python -m unittest discover -s tests -p "test_*.py"
```

Before CI dispatch, verify:

- all ten artifacts exist;
- primary identifiers are unique;
- all scenario and alternative foreign keys resolve;
- manifest hashes equal physical file hashes;
- authoritative scenario values equal exported values;
- repeated explicit inputs produce byte-identical output;
- no non-synthetic package is accepted.

## Explicit exclusions

- no PBIX file;
- no Power BI application dependency;
- no live supplier or commercial data;
- no supplier ranking or allocation;
- no autonomous technical approval;
- no formula changes;
- no browser-harness changes;
- no deployment, release, merge, reviewer request, or integration-contract finalization.
